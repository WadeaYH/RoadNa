    What the schema guarantees
    
      
      
        
    • One vote per account. A resident's vote on a proposal and an upvote on a report both use the person and the item together as the key, so a second vote cannot be stored. Changing a vote updates the same row.
      • 
        
    • One rating per report. rating.report_id is unique.
      • 
        
    • One team per person. team_member.user_id is unique, so nobody is on two crews.
      • 
        
    • One open job per report. A filtered unique index allows a new work order only after the last one is approved. Rework and reopening start a new order that points back with rework_of_id.
      • 
        
    • One role per person. app_user.role accepts only the seven roles, and the app decides screens from it.
      • 
        
    • One decision per proposal. proposal_decision.proposal_id is its own key.
      • 
        
    • Everything belongs to a municipality. Every report, person and proposal reaches a municipality, so many municipalities can share the platform without seeing each other.
      • 
        
    • Only known words. Status columns carry a check that lists the allowed values.
      •
